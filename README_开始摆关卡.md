# 白盒关卡工作区

项目已经接入 Godot AI MCP；使用本机 Godot 4.7.2 打开 `project.godot` 即可。实际编辑器为 `D:\Godot_v4.7.2-stable_win64.exe\Godot_v4.7.2-stable_win64.exe`（外层同名路径是文件夹）。

已完成MCP连接与编辑器摆放验收，接入及预设图案修复记录见 `docs/MCP_修复说明.md`。

## 直接开始

1. 打开 `scenes/levels/whitebox_template.tscn`，另存为你自己的关卡。模板只有可删除的起步地面、九个绘制图层、出生点、测试角色与相机。
2. 在左侧场景树选择对应的 `TileMapLayer`，底部打开 **TileMap**，选择图集来源与瓦片，在画布上绘制。16×16 网格已经配置好。
3. 实体地形可用 **Terrains / 地形 → Connect / 连接**；也可从 **Patterns / 图案**直接盖出一个 6×4 地块，再调整边缘。平台图案是左、中、右三格。
4. 把 `Spawn` 放到角色脚底应出现的位置；调整 `Camera2D` 覆盖测试区域。按 **F6** 运行当前关卡，**F5** 运行演示关卡。
5. `scenes/levels/whitebox_test.tscn` 是已摆好的演示；`scenes/reference/asset_catalog.tscn` 是全部原生素材的分类陈列，供编辑器中浏览。

鼠标右键擦除瓦片；大树、大云、太阳与门都是一次摆放的完整物件。多格物件以点击格的**左上角**为起点；它的绘制可以覆盖邻格，但地图数据只占锚点格，擦除时点原来的锚点。

## 测试角色

方向键或 A/D 移动；空格跳跃；W/S 或上下键攀爬；下+空格穿过单向平台；R 或 F2 回出生点；F1 切换碰撞显示。

角色12×22像素，速度110px/s，跳跃初速度260px/s，重力800px/s²，带0.1秒土狼时间与跳跃缓存。理论跳高约42px（2.6格），实测时以角色碰撞和平台顶面为准。参数可在 Player Inspector 修改。

物理层：1=实体地形，2=单向平台，3=测试角色，4=危险物。角色只被地形与平台阻挡；危险检测用 `behavior`，不把尖刺当墙。液体目前统一用于减速测试，熔岩没有单独伤害规则。

## 原素材与当前范围

地形原画只提供外角、边、中心与单块，缺少内凹角和单格宽/高连接组合。已配置四向地形连接，适合矩形地块；狭窄横向区域用平台，复杂凹角请手动选瓦片。不要把它当成覆盖任意形状的47块自动地形包。

门、宝箱、拾取物、开关、弹簧、检查点和移动平台素材已经可摆放；目前保留为关卡标记或静止平台，没有添加开门、收集、机关联动或运动轨迹。`spring_preview` / `checkpoint_preview` 仅是状态循环预览，不驱动游戏逻辑。这样可以先测试空间、路线和跳跃尺度。

原包文件与许可保存在 `assets/tiles/<pack>/source/`，该目录不重复导入。x4 PNG与GIF是放大/动画预览，未重复制作成新瓦片。三包均保留原始 LICENSE。

## 重建与验证

日常编辑不需要运行生成器。`tools/build_tilesets.gd` 会重写生成的 TileSet、演示、模板和目录陈列，**会重置这些文件中的手工修改**；自己的关卡请另存。

重建顺序：运行 `tools/prepare_assets.py` → 用 Godot 导入纹理 → 运行 `tools/build_tilesets.gd` → 用 Godot 再扫描资源。原素材位置写在 prepare 脚本中，可按需修改。

审计与验证记录见 `docs/asset_audit.json`、`docs/build_report.json` 和 `docs/validation_report.json`。`tools/validate_project.gd` 可以复查资源和运行测试。

Godot 官方参考：[TileSet](https://docs.godotengine.org/en/stable/classes/class_tileset.html)、[TileData](https://docs.godotengine.org/en/stable/classes/class_tiledata.html)。
